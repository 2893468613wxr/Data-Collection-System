### 关键技术坑（都是实际踩过的，值得记住）

**1. NuGet 的 TFM 平台版本会让包静默退回旧框架**
`net10.0-windows` 的平台版本默认是 **7.0**。`SkiaSharp.Views.WPF` 只提供 `net8.0-windows10.0.19041`，
7.0 < 10.0.19041 不满足兼容规则 → NuGet **退回 net462 程序集**并报 NU1701，靠 .NET 兼容层能跑起来（侥幸）。
修法：`<TargetFramework>net10.0-windows10.0.19041.0</TargetFramework>` + `SupportedOSPlatformVersion`。

**2. 截图工具不做 DPI 感知会导致"假故障"**
屏幕 1920×1080 @125% 缩放时，未声明 DPI 感知的进程 `Screen.Bounds` 只返回 1536×864，
截出来的图右下角是缺的 → 会被误判成"窗口布局有问题、状态栏被切掉"。
修法：进程启动时立刻 `SetProcessDpiAwarenessContext(-4)`（PER_MONITOR_AWARE_V2）。
另外：`GetWindowRect` 对最小化窗口返回 -32000，需先 `IsIconic` + `ShowWindow(SW_RESTORE)`。

**3. WPF 深色主题必须替换控件模板，只改颜色属性没用**
`ComboBox` 只设 Background/Foreground → 默认模板的 ToggleButton 背景是硬编码浅色，
文字却是我们设的浅色 → 浅底浅字，整个控件看起来"空白"。要整套 `ControlTemplate`（含 Popup + ComboBoxItem）。
（Button / TabItem / ListBoxItem / CheckBox 也要留意同样的问题。）

**4. ScottPlot 中文渲染**
`ScottPlot.Fonts.Default` 必须在 **Plot 构造之前**设置才对新 Plot 生效；
已经构造出来的 Plot 要逐个改 `Legend.FontName` / `Axes.Bottom.TickLabelStyle.FontName`。
中文缺字形的表现是"豆腐块"，缩略图里看起来像数字 0，极易误判为"图例内容错了"。

**5. 取消令牌被误当作通讯超时（本项目修复的真实缺陷）**
停止采集时正在飞的请求必然被取消，底层把"取消"翻译成"等待响应超时"，
上层就记了一次通讯失败并往环形缓冲写一个 NaN 断点，还会让 `ConsecutiveFailures` 自增 →
**用户点「全部停止」的瞬间可能误报"通讯中断"报警**。
修法：在"失败"分支里先判断 `if (ct.IsCancellationRequested) return;`。
（这个问题是靠**反复跑自检**发现的：约 25% 概率失败，表现为缓冲区最后一点是 NaN。）

**6. 自检里做真实 socket 测试很有价值**
内嵌一个迷你 Modbus TCP 从站监听回环随机端口（`TcpListener(Loopback, 0)`），
用可预期公式生成寄存器值（地址 N → 100*(N+2)），就能对"解析出的值"做精确断言，
而不是只断言"大概通了"。这比装 Modbus Slave 更早发现问题。

## 第二轮：界面可读性修复（用户实测反馈）

用户跑起来后报告两个问题：① 背景色和"一些标题文字"颜色重合，看不清标题；② 实时曲线的 X 轴日期看不清。
两个都是**真缺陷**，根因完全不同：

**问题 1 根因：`<Style TargetType="Window">` 的隐式样式对派生类窗口不生效。**
WPF 的隐式样式按元素的**精确类型**查资源，不会沿继承链落到基类上。`MainWindow` 的实际类型是
`WpfApp22.App.MainWindow`，永远匹配不到 `TargetType="Window"`。后果：
- 窗口 `Background` 回退成系统默认的**白色**；
- 而 `TextBlock` 的隐式样式（精确类型 `TextBlock`，**是生效的**）把文字设成了近白的 `#E6EDF3`；
- 顶部标题行 = 白底白字，对比度 **1.15:1**，等于隐形。
- 界面其余部分是深色，因为都包在设了 `Background` 的 `Border` / `DataGrid` 里被盖住了；
  只有 `DockPanel` 的直接子元素（标题行、行间空隙）裸露出来 —— 所以**只有标题出问题**。
修法：窗口样式加 `x:Key="Window.Base"`，`MainWindow` / `ChannelEditorWindow` 显式引用。

**问题 2 根因：`plot.Axes.DateTimeTicksBottom()` 是"移除所有底部轴 → 新建 → 加回"，整根轴对象被替换。**
原来代码的顺序是「先 `Axes.Color()` 上色 → 再 `DateTimeTicksBottom()` 换轴」，颜色设置被丢掉，
X 轴日期退回 ScottPlot 默认深色 → 深底深字。修法：把换轴提到最前。
另：`Axes.Color()` 会再刷一次轴上标签色，所以 `TickLabelStyle.*` 必须写在它之后；
属性名不统一 —— **`LabelStyle` 用 `ForeColor`，`Legend` 用 `FontColor`**（靠反射确认，别猜）。

**顺带调整的配色分级**（新增 `Brush.TextSecondary` = `#C9D1D9`）：
正文/主标题 `#E6EDF3`（>14:1）、分组标题与表头 `#C9D1D9`（>10:1）、次要信息 `#8B949E`（~5.7:1）。
高对比目标：`GroupBox` 标题 + `DataGridColumnHeader` 从 TextMuted 提到 TextSecondary。

**验证方式（关键经验）**：不再靠"看图"下结论，而是用像素采样算 WCAG 对比度（阈值 4.5:1）。
修复后实测：主标题 16.02:1、X 轴日期 10.55:1、Y 轴刻度 12.21:1。
环境无 Pillow，用标准库 `zlib + struct` 手写了个极简 PNG 解码器采样。
（**坑**：切扫描行时不能按 `y*(w*bpp)`，必须跳过每行开头的 filter 字节，否则整图错位、统计出假颜色。）

**截图工具又踩两个坑**（已并入技能）：
- `BitBlt` 从**屏幕 DC** 拷的是"最上层窗口"的像素 —— 目标窗口被编辑器遮住时，
  截出来的是**别的程序界面**（曾截到 WorkBuddy 白底菜单栏，让我误判很久）。
  修法：截图前 `SetWindowPos(HWND_TOPMOST)` 临时置顶（`SetForegroundWindow` 常被前台锁定拦下）。
- 最大化窗口的 `GetWindowRect` 返回 `Left/Top = -9`，负值直接当 `BitBlt` 源坐标 → GDI 行为未定义、输出错位。
  修法：把源区域夹进虚拟屏幕，余量补到目标坐标。`PrintWindow` 对 WPF 的 GPU 合成窗口只返回空白，不可用。

**最终状态**：`dotnet build` 0 警告 0 错误；SelfCheck **44/44**；两张文档截图已更新
（`docs/main-window.png` 主界面、`docs/channel-editor.png` 通道配置窗口）。

## 第三轮：Modbus 功能码支持（用户用 Modbus Slave 实测反馈的两个缺陷）

用户报告：① 从站（Modbus Slave）切到 0x01 就断通道；② 点位无法指定用哪个功能码读，
从站设成 0x04 时采集不到数。两个都是真缺陷，根因：

**问题 1 根因：把"从站的异常响应"当成了"链路故障"。**
点位永远发 0x03，从站只支持 0x01 时回异常帧 `0x83 0x01`（非法功能码）→
`ModbusDriver` 返回 Fail → `ConsecutiveFailures` 累加 → 触发自动重连 →
通道反复 Close/Open，用户看到的就是"一换功能码就断开"。
修法：`PointReadResult` 增加 `DeviceResponded` 标记（异常帧也是"设备回了话"），
`AcquisitionService` 据此分支：链路故障才重连；配置不匹配只报一次 Warning 且 `ConsecutiveFailures` 清零，
通道保持 Running。对应自检第 [11] 组（内嵌只支持 0x01 的迷你从站，断言 State 仍为 Running）。

**问题 2 根因：`RegisterKind` 只有 Holding/Input 两值，且界面上根本没有这一列。**
所以每个点位都是默认的 HoldingRegister（0x03）。
修法：枚举扩成 4 个值且**枚举值就等于功能码**（`Coil=0x01 / DiscreteInput=0x02 / HoldingRegister=0x03 / InputRegister=0x04`），
配 `RegisterKindExtensions`（FunctionCode / IsBitAccess / ShortCode / DisplayName）供组帧、解码、UI 三处共用；
`ProtocolFrame` 增加 `Bits`（位图展开，LSB 对应起始地址那一位，见 `ModbusBits.Unpack`）；
位类型 `RegisterCount` 恒为 1，采集值就是 1/0。

**UI 改动**：通道编辑器点位表新增「功能码（读取方式）」下拉列（带中文说明），
点位区上方加「默认功能码」下拉 + 「应用到全部点位」按钮（Modbus Slave 一个窗口只有一种 Function，批量改是刚需）；
主界面「点位实时值」表新增「功能码·地址」列（显示 `0x01 · 3`）。
坑：`PointDefinition` 是领域模型**故意不实现 INotifyPropertyChanged**，批量改完必须
`DataGrid.ItemsSource = null; ItemsSource = Points;` 强制整表重绘。

**最终状态**：`dotnet build` 0 警告；SelfCheck **65/65**（新增 [1][2][4] 的位解析与功能码映射、[11] 端到端）。
文档已同步：README（功能一览 / 配置说明 / 自检清单）+ docs/modbus-slave-guide.md 新增「功能码对照表」与排查行。

## 第四轮：按设备查看点位实时值（用户建议）

用户反馈：通道多的时候，点位实时值页直接平铺所有设备，查找困难。

**实现**：
- 主界面「点位实时值」页左侧新增设备列表（`DeviceFilterItem`），首项固定为「全部设备」，其余与 Channels 一一对应。
- 列表显示：状态灯、设备名、点位数；活动报警数 > 0 时数字变红加粗，兼作报警角标。
- 选中设备后右侧只显示该设备点位，搜索框可按点位名 / 地址 / 通道名过滤。
- 选中具体设备时「通道」列自动折叠（通过 `BindingProxy` 解决 `DataGridColumn` 拿不到 DataContext 的问题）。
- 曲线区增加「只看当前设备」复选框，跟随设备选择只画该设备趋势，标题显示「实时趋势曲线 · 设备名」。

**坑**：
1. `DataGridColumn` 不在可视化树上，不能直接 `Binding Visibility={Binding ChannelColumnVisibility}`。
   修法：加一个 `Freezable` 的 `BindingProxy` 放在 Window.Resources，`Data="{Binding}"`，列上
   `Visibility="{Binding Data.ChannelColumnVisibility, Source={StaticResource Vm}}"`。
2. 测试时错把旧的 `bin/Debug/net10.0-windows` 可执行文件当成当前产物，截出来的图一直显示旧布局。
   修法：该项目实际 TFM 是 `net10.0-windows10.0.19041.0`，运行/截图前要确认路径；清理了旧的 `net10.0-windows` 目录。
3. ListBoxItem 自定义模板里的 Grid 不设 `Background="Transparent"` 时，点击模板空白处不会选中项。
   修法：根 Grid 加 `Background="Transparent" HorizontalAlignment="Stretch"`。
