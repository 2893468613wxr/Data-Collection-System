# Modbus 联调指南

> 回答一个问题：**没有硬件，能不能用 Modbus Slave 这类软件模拟一台设备来验证上位机？**
>
> 可以，而且两条路都通。本文把「内置模拟器 → Modbus Slave TCP 直连 → Modbus Slave + 虚拟串口 RTU」三条路径按"从易到难"排好，并附一份排查表。

---

## 0. 先选一条路

| 方案 | 要装什么 | 验证的是 | 适合 |
| --- | --- | --- | --- |
| **A. 内置模拟器** | 什么都不用装 | 并发采集、报警、导出、界面 | 第一次跑通、录简历视频 |
| **B. Modbus Slave + TCP** | Modbus Slave | 真实 Modbus TCP 报文收发 | **推荐** —— 最容易做出"真的连上设备了"的效果 |
| **C. Modbus Slave + 虚拟串口** | Modbus Slave + com0com | 真实 Modbus RTU 报文收发（含 CRC） | 面试官追问"串口怎么调的"时用 |

三条路可以同时开着跑 —— 本系统就是多通道并发的，`1#反应釜`（模拟器）+ `2#冷却塔`（模拟器）+ `3#Modbus TCP`（Modbus Slave）同时采，正好演示"多协议并发"。

---

## 方案 A：内置模拟器（零依赖）

直接启动就是，不用做任何事。

```bash
dotnet run --project WpfApp22.App
```

点工具栏 **「全部启动」**，`1#反应釜`（100ms 轮询、4 个点位）和 `2#冷却塔`（200ms、3 个点位）开始出数。

状态栏会显示 `总吞吐 ≈ 55.0 点/秒 · 累计 … · 丢弃 0` —— 顺手可以讲一句"这个吞吐统计就是上面那套有界管道 + 批量写入的直接结果"。

## 方案 B：Modbus Slave + Modbus TCP 直连（推荐）

**不需要虚拟串口**。Modbus Slave 自己就是 TCP 从站，监听 502 端口，上位机作为主站连上去。

### B1. 准备 Modbus Slave

官网 <https://www.modbustools.com/modbus_slave.html> 下载安装（30 天试用版就够演示）。

> ⚠️ **不要同时开 Modbus Poll 和 Modbus Slave**。同一台机器上两个程序都想占 502 会打架。

### B2. 让 Modbus Slave 监听 TCP 502

1. 菜单 **Connection → Connect**（快捷键 `F3`）
2. `Connection` 下拉选 **Modbus TCP**
3. `Port` 填 **502**
4. 点 OK。标题栏出现 `[Connected]` 就成功了
5. 如果 502 被占用（报 bind 失败），改成 **5020**，稍后上位机端口也跟着填 5020

### B3. 定义从站和寄存器

菜单 **Setup → Slave Definition**（`F8`），照着填：

| 字段 | 值 | 说明 |
| --- | --- | --- |
| Slave ID | `1` | 要和上位机的"从站号"一致 |
| Function | `03 Holding Register` | 保持寄存器 → 上位机点位的功能码选 `0x03 保持寄存器 Holding` |
| Address | `0` | Modbus 地址是 **0-based** |
| Quantity / Size | `16` | 至少覆盖你要用的地址范围 |

点 OK。

> **关键点：Function 这一项必须和上位机点位的功能码对上。**
> Modbus Slave 一个窗口只有一种数据区，改了 Function 就要同步改上位机点位的功能码，
> 否则从站会回「非法功能码」，点位读不到数（但通道不会断线，见下方 [功能码对照表](#功能码对照表)）。

### B4. 给寄存器塞点值

在主表格里**双击单元格**直接改值。为了曲线好看，建议：

| 地址 | 填什么 | 上位机会显示 |
| --- | --- | --- |
| 0 | 逐个改成 200 → 850 → 40 … | 温度（UInt16 × 0.1）= 20.0 → 85.0 → 4.0 |
| 1 | 改成 800 | 压力 = 800 kPa |

想验证 32 位浮点的话，菜单 **Display → Floating Point** 可以把显示切成 Float 视图，方便对照。

### B5. 在上位机里配这个通道（关键一步）

首次运行时已经预置了一个 `3#Modbus TCP` 通道（默认**未启用**），直接改它：

1. 主界面左侧「采集通道」表格里选中 **`3#Modbus TCP`**
2. 点工具栏 **「编辑通道」**
3. 通道参数确认：
   - 名称：`3#Modbus TCP`
   - 传输：**Tcp**
   - 协议：**ModbusTcp**
   - 从站号：**1**
   - 主机：**127.0.0.1**　端口：**502**（若 B2 改了端口，这里同步改）
   - 轮询 ms：`500`
   - ✅ 勾上 **「启用该通道」**
4. 点位表格里确认两行，并且把 **「功能码（读取方式）」** 列设成和 B3 的 Function 一致：
   - `温度` / 功能码 `0x03 保持寄存器 Holding` / 地址 `0` / `UInt16` / 系数 `0.1` / 单位 `℃`
   - `压力` / 功能码 `0x03 保持寄存器 Holding` / 地址 `1` / `UInt16` / 单位 `kPa`
5. 点 **确定**

### B6. 跑起来

点工具栏 **「全部启动」**（或者只点 `3#Modbus TCP` 那一行的「启动」按钮）。

期望结果：
- `3#Modbus TCP` 那一行状态变成 **`采集中`**，`点/秒` 变成 **`4.0`** 左右
  （2 个点位 ÷ 0.5s = 4 点/秒）
- 右侧曲线出现 `3#Modbus TCP · 温度` 和 `3#Modbus TCP · 压力` 两条图例
- 在 Modbus Slave 里双击地址 0 改成 `900`，**曲线一秒内就跳上去**

到这一步，你就有一条**真实的 Modbus TCP 报文链路**跑通了 —— 打开 Wireshark 过滤 `tcp.port == 502` 能看到完整的 MBAP 请求/响应。

> 如果你还没装 Modbus Slave，也可以先跑 `dotnet run --project tools/SelfCheck`。
> 自检的第 **[10]** 组会在回环地址上临时起一个迷你 Modbus TCP 从站，
> 用真实 socket 走完 `TcpTransport → ModbusTcpCodec → ModbusDriver` 整条链路，
> 并精确断言"地址 0 解析出 200、地址 1 解析出 300"。
> 所以**代码层面的 TCP 链路是自带验证的**，Modbus Slave 只是把它接到一个你能手动改值的界面上。

## 功能码对照表（联调时最容易踩的一个坑）

Modbus Slave 的一个窗口只有**一种数据区**（Function），上位机每个点位也有自己的**功能码**。
两边必须一致，否则从站直接回「非法功能码」，那个点位一个数都读不到。

| Modbus Slave 的 Function | 上位机点位选的功能码 | 地址含义 | 采集到的值 |
| --- | --- | --- | --- |
| `01 Coil Status` | `0x01 线圈 Coil（读写开关量）` | 位地址 | `1` / `0` |
| `02 Input Status` | `0x02 离散输入 Input Status（只读开关量）` | 位地址 | `1` / `0` |
| `03 Holding Register` | `0x03 保持寄存器 Holding（读写）` | 寄存器地址 | 按数据类型解析 |
| `04 Input Register` | `0x04 输入寄存器 Input（只读）` | 寄存器地址 | 按数据类型解析 |

**怎么改**：`编辑通道` → 点位表格的 **「功能码（读取方式）」** 列逐行选；
或者用点位区上方的功能码下拉框 + **「应用到全部点位」** 一次改完整个通道
（Modbus Slave 换 Function 时，通常整个通道的点位都要跟着换）。

几个细节：

- 开关量点位（0x01 / 0x02）一次只读取 **1 个位**，数据类型和字序对它不起作用，值就是 1（通）或 0（断）。
- 主界面「点位实时值」页有 **「功能码·地址」** 列，显示成 `0x01 · 3`，
  随时能确认"这个点位到底是用哪个功能码、从哪个地址读的"。
- 功能码配错时的表现：报警中心出现一条**黄色**提示
  `… 读取失败：非法功能码（…）（设备已响应，链路正常，请检查该点位的功能码与地址配置）`，
  通道状态**保持「采集中」**，不会被反复断开重连 —— 因为从站明明回了话，链路是好的。
  把功能码改对后，下一次轮询（最多一个周期）立刻出数。

## 方案 C：Modbus Slave + com0com 虚拟串口（RTU）

Modbus Slave 的串口模式需要两个"接在一起"的串口：上位机开一个，Modbus Slave 开另一个。com0com 就是干这个的。

### C1. 装 com0com

<https://sourceforge.net/projects/com0com/>

> ⚠️ **Windows 10/11 上必须用签名版**，否则驱动装不上（会报"驱动签名无效"）。
> 优先找文件名带 `signed` 的安装包（如 `setup_com0com_W7_x64_signed.exe`）。
> 装的时候会问是否安装 **Ports class** 驱动，**勾上**。
>
> 如果驱动实在装不上，替代品：Eltima Virtual Serial Port Driver、HHD Virtual Serial Port Tools（都是商业软件，有试用期）。

### C2. 建一对虚拟串口

1. 开始菜单里找到 **`Setup com0com`**（不是那个 Setup Command Prompt）
2. 列表里 **Add Pair**，新建一对，默认形如：
   ```
   CNCA0  <-->  CNCB0
   ```
3. 把两个名字改成传统串口名，避免有些老程序不认 `CNCA0` 这种名字：
   - 双击 `CNCA0` → 改成 `COM10`
   - 双击 `CNCB0` → 改成 `COM11`
4. 确认勾选 **`use Ports class`**
5. Apply

现在设备管理器端口下会出现 `COM10` 和 `COM11`，**它们是互相连通**的 —— 往 COM10 写的数据从 COM11 读得到。

### C3. Modbus Slave 从站开在 COM11

**Connection → Connect**（`F3`）：

| 字段 | 值 |
| --- | --- |
| Connection | **Serial Port** |
| Port | **COM11** |
| Baud Rate | **9600** |
| Data Bits | **8** |
| Parity | **None** |
| Stop Bits | **1** |
| Mode | **RTU** ← 千万别选 ASCII |

Slave Definition（`F8`）跟方案 B3 一样：Slave ID `1`、Function `03 Holding Register`、Address `0`、Quantity `16`。

### C4. 上位机配 COM10

新增一个通道（工具栏 **「新增通道」**）：

| 字段 | 值 |
| --- | --- |
| 名称 | `4#RTU从站` |
| 传输 | **SerialPort** |
| 协议 | **ModbusRtu** |
| 端口 | **COM10** |
| 波特率 / 数据位 / 校验 / 停止位 | `9600` / `8` / `None` / `One`（必须与 C3 完全一致） |
| 从站号 | `1` |
| 轮询 ms | `200` |
| ✅ | 启用该通道 |

点位照抄：地址 `0` / `UInt16` / 系数 `0.1`。

### C5. 跑起来

「全部启动」。`4#RTU从站` 变成 `采集中`，点/秒约 `5.0`（1 个点位 ÷ 0.2s）。

这时候链路里跑的是**真正的 Modbus RTU 帧**：从站地址 + 功能码 0x03 + 起始地址 + 数量 + **CRC16**。在 Modbus Slave 里改值，上位机曲线实时响应。

> 想验证 CRC 实现：把波特率故意改成 `19200`（只在上位机改，Modbus Slave 不动），通道会立刻变成"通讯故障"并在重试若干次后进入自动重连 —— 因为 CRC 和帧同步都对不上了。这正好是个演示错误处理的时机。

## 排查表

| 现象 | 大概率原因 | 怎么办 |
| --- | --- | --- |
| 通道状态一直是「通讯故障」，日志刷"连接失败" | Modbus Slave 没点 Connect / 端口不对 | 确认 Modbus Slave 标题栏有 `[Connected]`；两边端口号一致 |
| 连得上但一直读不到数，报"从站异常响应" | 从站号不匹配 | 上位机"从站号"必须等于 Modbus Slave 的 Slave ID |
| 某个点位一直是 `--`，报警中心提示"非法功能码" | **点位功能码和从站的 Function 不一致** | 按[功能码对照表](#功能码对照表)把点位的功能码改成同一个；通道不会断线，改完立刻出数 |
| 在 Modbus Slave 里把 Function 从 03 换成 01，点位就不出数了 | 从站数据区变了，上位机还在发 0x03 | 编辑通道 → 点位表格改「功能码（读取方式）」，或用「应用到全部点位」批量改 |
| 开关量点位数值只有 0 和 1，数据类型怎么选都没用 | 正常现象 | 0x01/0x02 读的就是 1 个位，值域就是 1 / 0 |
| 数值全是 `0` | 地址不对 | Modbus Slave 里的 Address 是 **0-based**；手册上若写 `40001`，填进上位机要 **减 1** → `0` |
| 数值不是 0 但很离谱（如 `1.2E-38`） | 按 Float32 解了但字序不对 | 在「通道配置」里把该点位的 **字序** 在 `HighWordFirst` / `LowWordFirst` 之间切一下 |
| 数值顶格在 `6553.5` 附近不动 | 数据类型选窄了 | 设备其实是 32 位，把 `DataType` 改成 `Float32` / `Int32` / `UInt32` |
| 数值每隔一段时间跳一下 | 采样点不够，是**降采样丢点**不是丢数据 | 看状态栏"丢弃"计数，若是 0 就正常；曲线超过 1600 点时会做峰值降采样 |
| TCP 连不上，提示端口被占用 | 502 被别的程序占了 | Modbus Slave 换 5020，上位机同步改 |
| 串口报"拒绝访问 / 访问被拒绝" | **同一个串口不能被两个程序同时打开** | 上位机开 `COM10`，Modbus Slave 必须开 `COM11`（同一对的两端） |
| RTU 偶发 CRC 错误后自愈 | 波特率/校验/停止位有一项不一致 | 两边逐项对齐；本项目遇到脏字节会滑动重同步，所以能自愈 |
| Webhook 渠道不显示 | `config/notify.json` 里 `WebhookUrl` 是空的 | 填上机器人地址，或设环境变量 `WPFAPP22_WEBHOOK_URL` |

> 所有报警和通讯故障都会落到 `logs/alarm-YYYYMMDD.log`。**排查问题先去读这个文件**，别靠猜。

## 顺手可以演示的"故障剧本"

在 Modbus Slave 里就能制造真实故障，比点「注入通讯故障」更有说服力：

1. **拔线**：Modbus Slave 菜单 **Connection → Disconnect**。
   → 上位机通道转「通讯故障」，进入指数退避重连（1s → 2s → 4s → … 封顶 30s），曲线出现断点。
2. **插回去**：重新 Connect。
   → 上位机自动恢复，报警中心出现"通讯已恢复"，曲线接着画。
3. **越限报警**：把地址 0 的寄存器改成 `900`（× 0.1 = 90.0 ℃，超过 85 的阈值）。
   → 连续 3 次超限后触发（去抖），报警中心出现红色的「严重」行，蜂鸣器响，日志落盘。
4. **滞回演示**：把值改回 `83`（在 85 − 4 的滞回带内）。
   → 报警**不**恢复，说明滞回生效；继续降到 `80` 以下才恢复。
   → 这是最能体现"你想过现场真实工况"的一段。
